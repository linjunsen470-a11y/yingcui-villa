# 合盛·盈翠雅筑｜五层住宅空间漫游

根据随项目附带的原始户型图建立的、可在桌面浏览器实时运行的五层联排住宅模型。项目包含真实三维楼板、墙体、门窗、楼梯、阳台、屋面、室内家具、材质、照明与交互浏览器。

技术栈为 **React 19 + TypeScript + Vite 6 + Three.js 0.180**。React 管理界面，Three.js 直接管理场景、相机、门扇、碰撞与导出；模型从有尺寸的参数化数据生成。运行过程中无需 API 密钥、付费服务、外部模型 CDN 或远程纹理服务。

## 1. 快速运行

### 直接打开交付包

解压完整 ZIP 后，双击 **`offline/index.html`**。这个版本把 React、Three.js、界面、GLB 导出器都打成普通脚本，不使用网络 CDN，也不需要 npm、API 密钥或本地服务器。保留同目录中的 `app.js`、`app.css` 和 `floorplan.jpg`。需要支持 WebGL 2 且开启硬件加速的桌面浏览器。

如果电脑的文件安全策略阻止脚本或鼠标锁定，可使用下面的本地服务器方式；鼠标未锁定时也可按住画面拖动观察。

### 从源码运行

建议使用 **Node.js 22 或以上版本**，以及启用硬件加速、支持 WebGL 2 的近期桌面浏览器。

在项目目录运行：

```bash
npm ci
npm run dev
```

按照终端给出的地址打开网页，默认通常为 `http://localhost:5173`。首次安装依赖需要访问 npm；依赖安装后，应用使用项目自带代码、原图和本地生成的材质。

### 生产构建

```bash
npm run check
npm run build
npm run preview
```

构建输出位于 `dist/`。`npm run preview` 默认通常使用 `http://localhost:4173`；以终端输出为准。可以将整个 `dist/` 部署到支持静态文件的 HTTP/HTTPS 服务。

如果交付包中已经包含 `dist/`，也可以直接启动静态服务器，例如：

```bash
python3 -m http.server 8000 --directory dist
```

然后访问 `http://localhost:8000`。`dist/` 是采用模块的标准生产构建，请通过 HTTP/HTTPS 访问。需要直接双击运行时，请使用上面的 `offline/index.html`。

修改源码后，执行 `npm run build:offline` 可重新生成离线版。

首次打开显示首层的单层剖切模型，可见客厅、餐厅、厨房、卫生间与前后露台。所有几何采用**米**作为单位。

| 俯视平面 | 切换到俯视相机，便于与原图核对 |

### 第一人称漫游

点击「实景漫游」或「进入空间」。程序会请求浏览器锁定鼠标；如果浏览器不允许锁定，可按住场景拖动视角。

| 按键 / 控件 | 功能 |
| --- | --- |
| W / A / S / D，或方向键 | 向前、向左、向后、向右行走 |
| 鼠标移动 | 锁定鼠标后自由转头、上下看 |
| 按住场景拖动 | 未锁定鼠标时转动视角 |
| Shift | 加快移动 |
| E | 打开或关闭附近的门 |
| R / F | 导航到上一层 / 下一层 |
| 界面「上一层 / 下一层」 | 同样提供楼层导航 |
| Esc | 释放鼠标并返回自由观察 |

默认视高为 **1.64 m**。移动包含墙体、窗户、护栏、门扇及主要家具的基本碰撞检测；角色碰撞在水平面上以圆形近似。门关闭时会阻挡行走，贴近门洞时会阻止直接关门夹住角色。

**楼层导航采用传送到相邻层安全位置的方式。** 楼梯具有三维踏步、构件及扶手，当前未实现沿每级踏步连续升降的角色物理模拟。漫游期间使用 R/F、楼层按钮或相应界面按钮完成层间移动。

## 3. 五层空间与图纸依据

原图位于 `public/floorplan.jpg`，网页顶部也可打开。详细坐标、尺寸链、楼梯处理和不确定性记录见 **[docs/measurements.md](docs/measurements.md)**。

| 楼层 | 图纸主体尺寸 | 完成楼面标高 | 模型推定层高 | 主要空间 |
| --- | --- | ---: | ---: | --- |
| 地下室 B1 | 6.0 × 10.4 m | −3.00 m | 3.00 m | 健身房、酒窖、休闲区、多功能厅 |
| 首层 F1 | 6.0 × 10.4 m | 0.00 m | 3.35 m | 客厅、餐厅、开放厨房、卫生间、前后露台 |
| 二层 F2 | 6.0 × 12.0 m | +3.35 m | 3.10 m | 主卧、衣帽间、书房、两处卫生间、前阳台 |
| 三层 F3 | 6.0 × 12.0 m | +6.45 m | 3.10 m | 两间卧室、起居室、衣帽间、两处卫生间、前后阳台 |
| 阁楼 AT | 4.6 × 8.0 m | +9.55 m | 2.80 m | 休闲坐席、开放起居空间、观景台 |

### 对原图的关键复核

- 二、三层主体进深比首层多 **1.6 m**，位于图纸后侧；楼梯中段仍按统一轴线对应。
- 原图明确标注的卧室共**三间**：二层一间、三层两间。书房和阁楼起居按原有用途保留，未另设卧室凑齐营销标题中的“五房”。
- 二、三层各有**两处卫生间**；三层后左还有 **1.9 × 1.6 m** 的内凹阳台。
- 首层前露台包含图示 **2.0 m + 0.3 m**，后露台包含 **1.3 m + 0.3 m** 的尺寸分段。
- 二、三层后侧 **0.5 m** 的浅投影按凸窗 / 窄外挑构件处理。
- 首层卫生间的前缘比厨房更靠前，深度据图像比例推算约 **3.0 m**。

### 精度与面积边界

模型以原图可读尺寸控制外轮廓和主要分区。未标注的墙厚、门窗高度、部分洞口、层高、楼梯详图、立面和屋面属于推定；阁楼在下层屋顶上的精确落位未提供，按楼梯连续关系保守对齐。

建筑外墙采用约 **0.22 m**、内隔墙约 **0.13 m**、结构楼板约 **0.20 m**。地下室局部分墙以及三层前左衣帽间与卫生间的分界由图像比例推算。家具、装饰、灯具和材质为现代轻奢、自然木质、暖色系设计补全。

房间面积采用矩形范围扣除约定边距后的估值，并非逐项精确建筑面积核算。原图所述建筑面积约 198–215 ㎡、使用面积约 238–255 ㎡涉及未给出的计量口径；应用中的房间估值不能用于确认产权、合同或施工面积。

本成果适合空间浏览、方案沟通和后续三维编辑。用于施工、结构核验、装修放线或产权核算时，需要补充原始 CAD、立面剖面和现场测量数据。

## 4. 模型导出与后续编辑

### 已生成的模型

完整 GLB 位于：

```text
models/yingcui-villa.glb
```

该文件包含全部五层、原始楼面标高、完整墙体、门窗、天花、屋面、家具与内嵌材质图像。GLB 放在项目的 models/ 中随源码包交付，不随网页首屏加载。浏览器中的庭院展示地面、相机界面、碰撞逻辑和鼠标交互不属于 GLB 内容。

可在 Blender 中通过 **文件 → 导入 → glTF 2.0** 导入；模型按米制建立，并按楼层保留组层级。需要查看内部时，可以隐藏上方楼层或对应层的天花 / 屋面节点。为控制网页绘制调用次数，静态家具与建筑细节按材质合并；参数化源码保留了家具构造过程，适合进一步修改并重新导出。

### 网页导出

顶部「导出模型」会生成完整五层 GLB，并恢复原标高导出。导出的建筑不受当前选层、楼层分离或墙体剖切状态限制。导出计算在浏览器本地完成，处理时间取决于设备性能。

「更多选项 → 保存当前画面」可下载当前相机下的三维画面 PNG；该功能保存渲染画布，不包含网页工具栏。

### 在本地重新生成 GLB

CLI 导出为可选功能，网页运行与网页导出不需要额外安装 Canvas 库。要在 Node.js 中生成文件：

```bash
npm install -D @napi-rs/canvas
node scripts/export-model.mjs
```

也可指定输出位置：

```bash
node scripts/export-model.mjs --output ./artifacts/yingcui-villa.glb --stats ./artifacts/model-stats.json
```

脚本直接调用与网页相同的 `plans.ts`、`architecture.ts`、`furniture.ts`、`materials.ts`，通过本地 Canvas 生成纹理，再输出 GLB。临时编译目录会自动清理；脚本不使用浏览器、外部渲染服务或远程素材。

默认导出同时更新 **[docs/model-stats.json](docs/model-stats.json)**，记录各层标高、空间数量、Mesh 数量、三角形数量、世界坐标包围盒、内嵌纹理与 GLB 结构校验结果。修改建筑或家具源码后，请重新运行导出脚本，然后再构建网站，使下载文件与网页模型保持一致。

## 6. 修改模型

### 调整房间、门窗与层高

编辑 `src/plans.ts`。统一坐标为：`x` 向图纸右侧、`z` 向图纸下方、`y` 向上；首层与地下室后外墙轴线为 `z=0`。楼层子物体使用相对该层完成楼面的坐标，各层组的 `y` 为 `elevation`。

墙体由起点 `a` 和终点 `b` 定义。门窗开口中的 `offset` 是沿 `a → b` 从起点到**洞口起边**的距离，`width` 为洞宽，`bottom` 为窗台 / 洞底相对楼面的高度，`height` 为洞高。门窗是墙体分段留下的真实洞口。修改分墙后，也应核对房间进入位置 `spawn`、观看目标 `look` 和家具位置。

### 调整家具与材质

编辑 `src/furniture.ts` 中对应层的摆放代码，或修改同文件中的沙发、床、餐椅、柜体等构造函数。墙体与主要家具分别维护碰撞体；改变大型家具尺寸或位置后，需要相应更新碰撞边界。

`src/materials.ts` 生成木纹、织物、石材、瓷砖等纹理，并使用 Three.js 标准 / 物理材质的粗糙度、金属度、凹凸与透明参数。纹理在本地生成，具有固定随机种子；无需联网下载。灯光由 `src/viewer.ts` 中的日光、环境光和有限数量的室内灯控制。

### 验收建议

修改后先执行 `npm run check` 和 `npm run build`，再在浏览器中确认：

1. 五个楼层都可单独显示；整体和分离模式能看到五层。
2. 房间数量、位置和门洞与原图及 `docs/measurements.md` 一致。
3. 六个预设能进入正确空间，WASD 与鼠标转向正常。
4. 关闭门后不能直接穿过门洞，墙体与阳台护栏能阻挡行走。
5. 楼层导航可到达相邻层安全位置，俯视时没有上方楼板遮挡。
6. GLB 重新生成成功，统计中 `floorCount` 为 5，导出层节点齐全。

## 7. 性能与常见问题

默认采用流畅画质；精细画质增加屏幕空间环境遮蔽和像素分辨率，适合较好的独立显卡或桌面 GPU。模型通过静态几何按材质合并来控制绘制调用次数，纹理最大边长控制在 1024 像素。单层浏览能减少可见几何与灯光成本。实际帧率随屏幕分辨率、GPU、浏览器与电源策略变化，界面右下角显示实时帧率。

| 现象 | 处理方式 |
| --- | --- |
| 网页提示无法显示三维场景 | 检查浏览器 WebGL 2 支持与硬件加速，重载页面 |
| 漫游时鼠标没有锁定 | 单击画面再次请求锁定，或按住画面拖动转头 |
| 某些嵌入网页限制鼠标锁定 | 将页面在独立标签页打开，或使用拖动环顾 |
| 帧率较低 | 切换流畅画质和单层显示，缩小浏览器窗口或降低显示缩放负担 |
| GLB 文件导入后看不到室内 | 隐藏上方楼层和室内天花，调整观察相机 |
| CLI 提示缺少 Canvas | 安装可选的 `@napi-rs/canvas`，或直接使用网页 GLB 导出 |
| 修改源码后下载模型仍是旧版本 | 重新运行 `node scripts/export-model.mjs`，再执行 `npm run build` |
