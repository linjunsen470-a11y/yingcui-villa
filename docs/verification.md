# 交付验证记录

日期：2026-10-28。以下区分实际完成的检查与没有覆盖的范围。

## 已完成

1. **TypeScript 与生产构建**：`npm run check`、`npm run build` 均成功。构建包含本地 JavaScript、CSS 及原始户型图，没有运行时 CDN、付费接口或密钥。
2. **五层模型完整性**：地下室、首层、二层、三层、阁楼均成功实例化；房间/走道/室外空间共28个节点。门窗采用实体洞口，不以原图贴地替代结构。
3. **平面尺寸及布局**：核对6.0×10.4米、6.0×12.0米、4.6×8.0米尺寸链；二层/三层各两卫、三层后左内凹阳台以及阁楼前观景台均保留。
4. **通行连通性**：以0.06米二维网格、0.19米玩家半径检测墙体、家具、栏杆及打开门扇的实际包围盒。按相邻楼板的并集检测边界，楼梯前留0.75米平台。全部28个入口点无碰撞，并从各自楼层主起居区/楼梯厅可达。
5. **实际桌面浏览器**：已在桌面Chrome打开正式网页，确认三维加载、完整建筑、楼层分离、客厅第一人称视角、鼠标拖动转头、门的开关及R键上楼导航。运行日志未返回应用错误。首轮视检后移除了6处与窗洞重叠的装饰画，并调整展示镜头留白及曝光。
6. **GLB模型**：通过同一套建筑/家具/材质源码导出，并检查GLB 2.0文件头、长度、JSON与二进制分块、五层节点、内嵌材质图像与几何顶点有限性。详见 `model-stats.json`。
7. **实际移动函数集成检查**：直接调用 `VillaViewer` 现有的 `move()`、`blocked()`、`updateDoorBoxes()`，使用完整建筑和家具。二层走道持W模拟1秒，实际前进1.800000米；首层入户门关闭时，角色停在z=10.18米，符合45mm门扇与0.19米角色半径计算；开门后可跨越门槛到前露台z=12.49米，随后被外边界正常拦住。

## 修复的问题

- 相邻书房/卧室打开的门扇遮挡卫浴入口：更换铰链端与开门方向，保留门洞位置。
- 首层客卫出门落脚区与楼梯相交：保留原门位，向内开门，并按图纸楼梯可见占位保留过渡带。
- 主体与阳台相接处的碰撞裂缝：将逐块内缩判断改为楼板并集判断。
- 三层衣帽间门前无足够落脚区：补充实际楼板平台，并同步碰撞范围。
- 茶几、贵妃位、橱柜与电视柜碰撞范围不一致：按实际几何修正。
- 六处装饰画与窗洞重叠：移除，不改变建筑窗位。

## 验证边界

- 当前成果为实时三维建筑可视化，不是测绘或施工级BIM。没有立面、剖面及楼梯详图的部分仍属于明确记录的推定。
- R/F及界面按钮提供层间定位；当前不模拟连续逐级攀爬、重力或坠落。
- 碰撞为水平圆形角色与矩形包围盒，优先保证墙体、关闭的门、主要家具及护栏的基本阻挡；不是精细人体物理模拟。
- 测试浏览器受自动化会话与后台节流影响，界面帧率读数不能作为目标电脑的稳定性能承诺。已经通过几何合批、单层显示、有限灯光和可选精细画质控制开销。
- 初始云预览浏览器未提供WebGL上下文；最终三维显示与交互检查是在可用的桌面Chrome中完成。
- 触屏可拖动观察与使用房间/楼层定位；WASD完整自由步行以桌面键盘鼠标为主要操作方式。
